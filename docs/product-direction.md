# RayTab 产品定位与本轮目标

2026-10-03，按用户明确方向：以网站图标管理为核心，简洁、流畅的开源新标签页。图标基本覆盖常用网站即可；优先提高整理效率、显示一致性和本地重载体验。

## 产品边界

- 核心任务：添加、编辑、排序、分组、文件夹及右键管理网站图标。
- 辅助能力：搜索、时钟和壁纸；现有私密保护、备份、导入及用户配置的同步保持可用。
- 数据原则：默认本地保存，无需账号或自建服务器；不向图标服务发送完整网址、书签列表或私密内容。
- 交互原则：默认好用、控件对齐、状态反馈清楚；按需展示裁切、上传、同步维护等次级操作。
- 实现原则：沿用 WXT、React、Zustand、RHF、Zod、Radix、idb 等已接入机制，不增加同职责框架。

## 本轮实现

1. 图标目录与扩展版本解耦：普通空间主动获取图标时，低频读取 SVGL 公开索引并本地匹配。现有本地精选目录用于离线和国内品牌补充；不部署新后台，也不调用未经确认可供第三方使用的 GoTab 内部接口。
2. 未收录网站通过网页、Touch Icon、Manifest 和已接入的 Vemetric 自动获取。检查原始尺寸、服务缩放和占位图，不把上采样当高清。获取失败保留当前图标与草稿。
3. 品牌标记、底色和留白一并处理：完整图片保持原样，透明标记显示在不透明底色上，用户上传或手动设置优先。
4. 编辑入口紧凑明确，只保留网站、文字、上传三种来源；导航对象通过右键和键盘管理。设置保持统一控件节奏，语言与安全有正常归属。
5. 图标与壁纸使用现有本地保存入口；新标签页打开不发起图标服务查询，不为显示建立第二套用户数据。

本轮不增加小组件商店、账号服务或用户自部署要求，不迁移实际用户数据，不提交、推送或发布。

## 参考取舍

| 来源           | 借鉴内容                             | RayTab 的取舍                                            |
| -------------- | ------------------------------------ | -------------------------------------------------------- |
| Bonjourr       | 对象右键编辑、自动获取与精选素材配合 | 使用已有成熟交互，不复制其自建服务                       |
| Renewed Tab    | 在线目录本地匹配、图片缓存           | 目录按需更新；用户图片沿用已有 IndexedDB 资源入口        |
| Tabliss、Mue   | 任意域名通过通用来源获取             | 复用现有公开 API，不为新增网站加专用代码                 |
| GoTab          | 精选矢量图标和品牌底色、服务端资源库 | 借鉴显示数据；接口稳定性与第三方使用范围未确认，暂不接入 |
| Anori、Toby 等 | 全局偏好有归属、按任务展开表单       | 保留必要设置与数据任务，降低首屏复杂度                   |

来源与可核实范围见 `research/newtab-open-source.md`、`research/newtab-products.md` 和 `ui-reference.md`。公开 API 说明：[SVGL](https://svgl.app/docs/api)、[Vemetric](https://vemetric.com/favicon-api)；GoTab 的部署资源说明见[官方仓库](https://github.com/dengxiwang/gotab-personal)。

## 完成条件

- 未打包的新域名可以通过在线目录或通用获取保存，刷新和离线重载仍显示本地图片。
- 公共目录请求不包含用户域名；公共图标 API 只接收允许的域名，私密、IP、内网和非标准端口入口不走第三方。
- 低清、损坏、占位图、超时和保存失败有明确处理，不覆盖已保存图片，不丢失草稿。
- 网站编辑、右键移动/删除确认、文件夹与分组拖拽、设置保存重载在真实扩展上下文验收。
- 截图检查编辑与设置布局、明暗主题、窄屏；类型、相关逻辑测试、格式以及 Chrome/Firefox 构建通过。
- 国内运营商网络质量单独记录；模拟源站失败而 API 可达只能证明回退逻辑，不能证明国内网络可靠性。

实际完成结果记录在 `modernization-validation.md`，不以目标清单或打包成功代替交互验收。
